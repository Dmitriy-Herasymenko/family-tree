# Рідні — сімейне дерево

Українськомовний застосунок на React, TypeScript, Vite та Express. Сервер зберігає акаунти й приватні дерева в Neon PostgreSQL. Інтерактивне дерево, родичі, історії життя, кілька дерев, пошук та експорт JSON адаптовані до телефона й комп’ютера.

## Локальний запуск

Потрібен Node.js 20.19+.

```sh
npm install
cp .env.example .env
```

Якщо `.env` уже налаштований, не перезаписуйте його. Додайте свій connection string Neon як `DATABASE_URL`. Цей файл ігнорується Git; пароль ніколи не додавайте у змінні `VITE_`.

```sh
npm run db:push
npm run dev
```

Відкрийте **http://localhost:5173**. Vite передає `/api` серверу на `127.0.0.1:3001`. Для іншої адреси змініть `APP_ORIGIN` у `.env`. Порт Vite зафіксовано, щоб адреса збігалася з дозволеним джерелом запитів.

Поточний проєкт Neon: `family-tree`, Project ID `falling-night-38536590`, гілка `production`, Branch ID `br-frosty-rain-b4qs59fi`.

## Обліковий запис і дані

1. Неавторизований користувач автоматично переходить на окрему сторінку `/login`. Реєстрація розташована на `/register`.
2. Під час реєстрації введіть ім’я, email, назву родини та пароль від 8 символів. У новому акаунті створюється приватне дерево з вибраною назвою.
3. Після входу відкривається кабінет. Останнє вибране дерево запам’ятовується окремо для кожного акаунта й відновлюється після оновлення сторінки.
4. Додавайте людей, батьків, партнерів і дітей. Після успішного запису сервер повертає збережену версію дерева.
5. У профілі є кнопка «Імпортувати дерева з демо». Вона копіює локальні дерева в поточний акаунт. Повторне натискання створює нові копії.
6. Після виходу відкривається сторінка входу. Серверні дерева не зберігаються у localStorage.

Якщо API або база не налаштовані чи недоступні, сторінка авторизації показує повідомлення та кнопку повторного підключення. Автоматичного переходу в деморежим немає. У файловій версії `dist/ridni-demo.html` окремо збережено локальне демо без справжньої авторизації.

Локальне демо зберігається в браузері для конкретної адреси й порту. Файл, localhost та інший порт мають різні сховища. Очищення даних браузера видаляє локальні дерева. Фотографії демонстраційних осіб — Unsplash, шрифти — Google Fonts.

## Сервер

- `server/schema.sql`: таблиці `ridni_users`, `ridni_sessions`, `ridni_trees`, `ridni_photos`; міграція додає їх без видалення наявних даних.
- Паролі хешуються через scrypt з випадковою сіллю. Сесія — випадковий токен у HttpOnly cookie; в БД зберігається лише SHA-256 токена. Термін сесії — 30 днів.
- Кожен запит до дерева перевіряє власника за сесією. Ідентифікатор користувача з тіла запиту не приймається.
- Запити на зміни потребують дозволеного Origin і заголовка клієнта. SQL використовує параметри. Вхід і реєстрація обмежені за кількістю спроб у межах одного процесу.
- Сервер перевіряє дати, зв’язки, цикли предків, взаємність партнерства і розміри даних. Для демо встановлено ліміт 1000 людей на дерево.
- Версія дерева захищає від одночасного перезапису в різних вкладках: конфлікт повертає HTTP 409, поточні дані не перезаписуються.
- TLS перевіряє сертифікат PostgreSQL (`verify-full`).

Основні маршрути: `GET /api/status`, `GET /api/auth/me`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `PATCH /api/auth/profile`, `GET /api/trees`, `POST /api/trees`, `POST /api/trees/import`, `PUT /api/trees/:id`.

## Перевірки й production

```sh
npm test
npm run build
```

Збірка також створює переносне локальне демо `dist/ridni-demo.html`. Справжня авторизація потребує сервера.

Для запуску production задайте `APP_ORIGIN=https://your-domain`, налаштуйте HTTPS-проксі до сервера й виконайте `npm start`. У production cookie має атрибут Secure. Для кількох інстансів потрібен спільний rate limiter. Підтвердження email, відновлення пароля та розгортання поки не реалізовані.

## Фото людей

У формі людини є вибір файлу, попередній перегляд, заміна та прибирання фото. Підтримуються JPG, PNG і WebP до 10 МБ. Браузер обрізає зображення по центру до квадрата, зменшує до 640 × 640 пікселів і конвертує в JPEG до 256 КБ. Фото відправляється тільки під час збереження картки; скасування форми його не завантажує.

Сервер перевіряє JPEG і розмір, зберігає байти в окремій таблиці Neon та повертає приватну адресу `/api/photos/:id`. Завантаження фото, зміна дерева та перевірка версії виконуються в одній транзакції. Фото доступні лише власнику за активною сесією. Після прибирання або заміни останнього посилання файл видаляється з бази. У файловій демоверсії фото зберігається локально; імпорт демоданих переносить його до акаунта.

JSON-експорт серверного дерева містить приватні адреси фотографій, а не файли. Вони працюють у тому самому акаунті на тому самому сервері. Для великого обсягу медіа надалі доцільно використати окреме об’єктне сховище.
